# PFスクラップ管理

工場のスクラップ重量を日次で記録し、品目マスター・初品実測重量・McFrameの完成品数量・月次在庫入力と組み合わせて、**理論スクラップとスクラップ売却数量のズレ**を管理する業務アプリ（Palomaシリーズ）。

- **ホーム**（`/`） — 使う順番（① マスタ → ② 日次記録 → ③ 袋の記録 → ④ 初品重量測定 → ⑤ 調達入力(購入・売却・月次在庫) → ⑥ McFrame取込 → ⑦ 月間集計 → ⑧ 照合）を番号付きで示し、各画面へ案内。いまの工場の今月の状況（今日の記録・記録日数・合計・承認待ち）と最近の日次記録も出す
- **工場の選択** — 全工場を見られる人は、開いたら最初に工場（または全工場）を選ぶ。全画面の上部に「いまの工場」と「工場を切り替え」を表示（下記「工場の選択」）
- **日次記録** — 紙のスクラップ日次記録票と同じ構成（朝礼確認 / 日中記録 / 終礼集計 / 備考）。当日合計・差異率は自動計算、月間集計・CSV出力つき
- **品目マスター** — KEY = 管理図番 + 製造場所CD（McFrameの設定）を自動生成。子図番での検索呼び出し、CSV一括取込/出力
- **品質チェックシート取込**（管理者） — 大口工場の品質チェックシート（PDF）の「備考」欄に書かれた完成品重量を、複数ファイルまとめて読み取り、加工日×図番の初品測定として登録（G長確認済みのため承認済みで反映）。品目別の件数・平均・最小/最大を確認でき、理論値と桁が違う行は初期状態で除外
- **初品重量測定** — 毎日生産した初品の単品完成品重量を登録。完成重量の計算には**その生産日以前の最新実測値**を使用（測定した日以降の生産分に効く。未測定はマスター理論値）
- **McFrame取込** — 完成品数量（加工数）のCSV取込。品目別に完成重量・使用量・理論スクラップを算出
- **月次入力** — 区分別（銅条/銅管/その他）の月初在庫・購入重量と、スクラップ売却数量
- **照合ダッシュボード**（`/dashboard`。旧 `/`） — ⑥売却×日次記録、⑦理論スクラップ×売却/日次記録の突合と年間推移。差異5%超はハイライト
- **初品測定一覧** — 初品測定の記録を月・工場・品目・状態で絞り込み、そのままCSV出力
- **品質チェックシート取込** — 品質チェックシート（PDF）の備考欄に書かれた完成品重量を、複数PDF／フォルダごとのドラッグ＆ドロップで読み取り、初品測定として一括登録（管理者）。PDFはブラウザ内で読み、ファイル自体は保存しない

## 工場の選択

- 見てよい範囲は従来どおり所属で決まる（`getFactoryRestriction`）。**所属工場（users.factory）がある人は所属工場のみ**（管理者も同じ）、未設定（ポータル管理者・本部スタッフ）とデモは全工場
- 全工場を見られる人は、開いたら最初に「工場を選んでください」画面（工場カード＋「全工場」）が出る。選んだ工場は Cookie `sc_factory`（全工場は `__all__`）に保存し、画面を読み込み直す。工場の一覧は各画面の工場フィルタと同じ `listFactoryOptions`（設定の「工場・職場」で使うにした工場＋記録にだけ出てくる工場。使わないにした工場は出さない）。選んでいた工場が使わないになったときは、選び直しの画面を出す
- 所属工場の人には選択画面も切り替えボタンも出さず、上部に「所属工場のデータを表示しています」と出す
- 各画面（ダッシュボード・日次記録・日次記録のExcel取込・袋の記録・月間集計・初品重量測定・調達入力・品目マスター/QR・重量計マスター/ラベル）は `getFactoryView` で工場を決める。工場を選んでいればその工場に固定し、「全工場」のときだけ従来の画面ごとの工場フィルタ（`?factory=`、FactorySelect / ScaleFactoryFilter）で絞り込める
- Cookie は範囲の中での絞り込みにだけ使う。書き込み（日次記録・調達入力・初品測定・AI読取など）の工場の判定は従来どおり `getFactoryRestriction`。CSV出力も所属工場の人は所属工場に固定
- McFrame取込は会社単位のデータ（工場の列が無い）、設定は工場・職場のマスタそのものを扱う画面なので、工場では絞らない
- `GET /api/scope` → `{ all, home, factory, factories }`

## 技術構成

- Next.js (App Router) + Tailwind CSS 4 + `@paloma-pf/ui`（共通シェル） — 他のPalomaシリーズと同一パターン
- Supabase Postgres（`DATABASE_URL` + `DB_DRIVER=pg`）/ next-auth（JWT・12時間・アプリ固有Cookie名 `scrap.session-token`）
- ログインはポータル（portal.paloma-pf.com）のSSO一括ログインに一本化。パスワードログインは統一管理者（admin）のみ（SSO障害時の復旧用）
- 無操作の自動ログアウト（`@paloma-pf/ui` の useIdleLogout）→ ポータルの一括ログアウトへ

## 計算式（月次集計Excelの式を踏襲）

- **使用量(在庫法)** = 月初在庫 + 購入重量 − 翌月月初在庫
- **使用量(構成法)** = Σ(加工数 × 構成重量) ※翌月在庫が未入力の場合のフォールバック（画面にバッジ表示）
- **完成重量** = Σ(その日の加工数 × その日に有効だった単品完成重量) ※初品実測値（その生産日以前の最新）を優先、未測定はマスター理論値。月次も日ごとに掛けてから合計するので、日別表と月次表の合計は一致する（日付を持たない過去データ移行の月次取込値だけは月末時点の実測で評価）
- **理論スクラップ** = 使用量 − 完成重量
- **⑥ 差異** = スクラップ売却数量 − 日次記録スクラップ合計
- **⑦ 売量vs理論** = スクラップ売却数量 − 理論スクラップ

> 前提: 使用量(構成法)は「加工数 × 構成重量」の合計で計算しています（構成数の乗算は行いません）。運用と合わない場合は `src/lib/calc.ts` の `monthlyItemRows` を調整してください。

> 在庫法を使うのは、**翌月の月初在庫が棚卸として入力済み**のときだけです。未入力の月は前月から理論ロールした在庫を使うことになり、`月初 + 購入 − (月初 + 購入 − 構成法使用量)` と循環して中身が構成法と同じになるため、構成法として表示します。
>
> 購入・売却は、その月に調達入力（日次）が1日でもあれば日次の合計を使います（月次入力の値は使いません）。入力が月の一部だけの月は、ダッシュボードに「31日中5日分だけ」と出して入力漏れに気づけるようにしています。
>
> 加工数は、日別と月次取込（過去データ移行用）が同じ月に併存する場合、二重計上を避けるため日別だけを使います。その月はダッシュボードとMcFrame取込画面に「月次の取込値は未使用」と表示します。
>
> McFrameの加工数が未取込の月は、完成重量・理論スクラップ・構成重量(参考)を「-」で表示します（0にすると「完成品ゼロ」と読めてしまうため）。工場で絞ったとき、その工場の品目マスターに無い加工数は集計から外し、除外件数をダッシュボードに出します。

## 品質チェックシート（PDF）からの初品重量の取込

- 大口工場では、初品の単品完成品重量を品質チェックシートの「備考」欄に書いている（例: 備考「0.0750」= 0.075 kg）。画面「品質チェックシート取込」（管理者）に、ファイルサーバーの月フォルダ（`…\02_PDF\2026\202609`）のPDFを複数まとめて／フォルダごとドラッグ＆ドロップすると、加工日・図番・備考の重量・検査者を読み取り、品目マスター（図番＝品目CD、無ければ子図番）と照合した一覧を出す
- 内容を確認して「登録」すると、加工日×品目の初品測定として**承認済み**で登録され、完成重量の計算に反映される（G長確認済みの記録のため）。同じ加工日×品目が複数あれば平均して1件にする。理論値と桁が違う行（3倍超／1/3未満）は初期状態で登録対象から外れる
- 品目マスターに無い図番も、図番のまま（格納場所CDは空）登録できる。一覧では「マスター未登録」と出て、備考にシートの品名を残す。完成重量の計算には、品目マスターにその品目CD×格納場所CDが登録されたうえで同じ組で測定が登録されたときに使われる
- PDFはブラウザ内で読み（pdf.js）、サーバーへは読み取った値だけを送る。**ファイル自体は保存しない**。文字を持つPDF（Excelから出力したもの）が対象で、スキャン画像のPDFは読めない
- 登録した記録は「初品測定一覧」（`/first-list`）で月・工場・品目・状態で絞り込んで確認し、`GET /api/export?type=first&ym=YYYY-MM|all&factory=&q=&status=` でCSVに出せる

## CSV取込フォーマット

**品目マスター**（管理者）: 1行目に見出しがあれば列順は自由（.xlsx / CSV どちらでも取込可）（管理図番, 品名, KEY, 区分, 親図番, 親品名, 子図番, 子品名, 単位, 構成重量, 完成重量(理論), 製造場所CD, 製造場所名, 工場）。KEY 未指定時は自動生成。

**McFrame 完成品数量**（管理者）: 取込時、**品目マスターに無い品目は実績の品名・格納場所・製造場所から自動登録**します（McFrameを正とするため）。実績出力に重量は無いので構成重量・完成重量は0のまま＝品目別表の重量根拠は「重量未設定」になります。あとで品目マスター（BOM出力）を取り込むと、この自動登録行は本物の行に置き換わります（`scrap_items.auto_added`）。

**McFrame 完成品数量の形式**: McFrameの製造実績出力（品目ＣＤ・格納場所ＣＤ・出来高計上日・基準単位良品数量。英語見出し `itm_p.itm_cd` / `strg_loc_cd` / `yield_ac_dt` / `base_unit_yield_qty_p.qty` でも、英語＋日本語の2段見出しでも可）をそのまま。簡易形式は `品目CD,格納場所CD,日付,加工数`（過去データ移行の月次は 日付 の代わりに 年月）。同じ日付×品目CD×格納場所CDは上書きされるので、工場ごとのファイルは1つずつ取り込みます。

**初品重量測定**（管理者・過去分の移行用）: 現場のExcelをそのまま。品目CD（管理図番）の見出し行があり、日付ごとに実測重量が並ぶ表を読みます。「品目が行・日付が列」の様式と、「日付ごとに 加工数 / 完成重量 が並ぶ」様式のどちらでも可（ブック内の全シートを読み、同じ品目・同じ日の重複は1件に畳みます）。空欄・0・「生産なし」は測定なしとして飛ばします。取り込んだ値は**承認済み**で登録されます（取込操作＝管理者による一括承認）。

> 桁ズレの補正: 品目マスターの完成重量(理論) →（無ければ）構成重量 →（無ければ）その品目の測定値の中央値、を基準に、**10のべき乗ぶんズレている値だけ**他の日の水準に合わせます（補正した行は測定記録に「桁補正 0.175 → 0.0175」と残ります）。10のべき乗で説明できないズレは直さず、取込結果に「要確認」として件数を出します。測定値どうしの中央値だけを基準にしないのは、同じ品目がまとめて桁違いに記録されているとき（多数派が誤り）に逆へ直してしまうためです。

取込は **.xlsx のままでも CSV でも可**（Excelで保存し直す必要はありません。追加ライブラリは使わず `src/lib/xlsx.ts` で読みます。旧形式の .xls は非対応）。CSVの文字コードは UTF-8 / Shift_JIS を自動判定。CSV出力は UTF-8 BOM 付き（Excelでそのまま開ける）。

## 日次記録のExcel取込（過去分の移行）

アプリ導入前・アプリで入力できていない期間の記録票（現場のExcel「スクラップ日次記録票」）は、
**日次記録 → Excel取込**（`/daily/import`。生産管理部・調達部のメンバーと管理者）から取り込めます。
ブラウザ側でExcelを読んで内容を画面で確認してから、確認した内容だけをサーバーへ送ります（`.xlsx` / `.xlsm`）。

- **1シート＝1日分の記録票**。同じ日のシートは**1枚の記録票**にまとまります（アプリの記録票は日付×工場で1枚のため）
- **箱の種類の決め方**はブックごとに選びます
  - 大口: 種類ごとのブック（上銅 / 銅ダライ / 銅スクラップ）→「ブック全体で1つ」（シート名から自動判定）
  - 直方: 部署ごとのブック（プレス / ベンダー / 炉中）→「明細の品種列から」。シート名に「下銅」があればそのシートは下銅、
    それ以外は品種列（銅条 / 銅管）、品種が空の行は指定した既定の種類。
    種類の名前は工場をまたいで大口の箱に合わせる（画面の読み替え表。既定は 銅条→上銅、銅管→銅ダライ、下銅→銅スクラップ）
- 列の位置・見出しはブックによって違う（大口「投入重量／実投入／累積差」、直方「重量／ｽｸﾗｯﾌﾟ重量」）ため、
  **見出しの文言から列を探します**
- **日付はシート名**（「上銅7.23」「日次記録票 【9.8】 (14)」「【0602】」）から決めます。日付セルは前日のシートを
  複製したまま直っていないことが多いため（直方は全シートが原紙の日付のまま）、食い違う場合は警告に出したうえで
  シート名を採用します。年はシート名に無いので画面で指定します（ブックの途中で月が戻れば翌年扱い）。
  行の余白に記入日（「9/7記入」「6/9計測」や日付のシリアル値）があれば、シート名よりそちらを優先して
  その日の記録にします（「【5.29・6.1分①】」のような複数日のシートも行ごとに分かれる）。
  同じ日に同じ内容のシートが2枚あれば（複製）1枚だけ取り込みます
- **重量 = 重量 − 箱重量**（サーバー側で計算し直します）。「実投入／ｽｸﾗｯﾌﾟ重量」列が手入力で上書きされていて
  食い違う行は警告に出ます。累積（投入前/投入後）はExcelの「累積」列と同じく種類ごとの積み上げで入ります
- **回収箱測定値**には大口の「回収箱測定値」、直方の「計量重量」（計量時総重量 − 袋重量×袋数。総重量が
  未記入なら空）を入れます。箱・シートごとの値なので、その日の合計を入れ、1つでも未記入があるとその日は空にします
  （部分的な合計で差異率を出さないため）
- Excelに**責任者のサイン**がある日は承認済みとして取り込みます（承認者は「サイン名（Excel）」）。
  サインが無い日は下書きですが、「サインが無い日も承認済みとして取り込む」を選ぶと取込者の承認になります
- 記録票の**部署 / 機械 / 品種 / 工程**は明細に残り、日次記録の一覧に添えて表示します
  （アプリの新しい入力では使わない項目ですが、取り込んだ記録を編集・再保存しても消えません）
- 種類マスタに無い種類は取込時に「設定 > スクラップ種類」へ追加され、その種類の重量計が1台だけ
  登録されていれば明細はその箱に紐づきます
- すでにアプリに記録がある日は既定で**取り込みません**（画面で「置き換える」を選ぶと上書き）

## 開発

```bash
npm install
npm run dev   # http://localhost:5188
```

### 環境変数（.env.local）

| 変数 | 用途 |
| --- | --- |
| `DATABASE_URL` | Supabase Postgres（スクラップ専用DB）。**Session pooler** の接続文字列を使う |
| `DB_DRIVER` | `pg`（Supabase では明示推奨。未指定でもホスト名から自動判定される） |
| `NEXTAUTH_SECRET` / `NEXTAUTH_URL` | next-auth |
| `PF_PROVISION_KEY` | ポータル連携の共有キー（pf-portal と同じ値） |
| `PF_ADMIN_BOOTSTRAP_HASH` | 統一管理者（admin）ブートストラップ用 bcrypt ハッシュ（任意） |
| `ON_PREMISE` | `1` で社内運用（課金ゲートなし） |

### Supabase の接続について

- Supabase → Project → **Connect** → **Session pooler**（`...pooler.supabase.com:5432`）の接続文字列を使います。Vercel のサーバーレスから直接接続（`db.<ref>.supabase.co`）は接続枠を使い切りやすいため使いません。
- 接続文字列の末尾に `?sslmode=require` を付けます（pg が接続文字列から解釈します）。
- DB アダプタ（`src/lib/neon.ts`）はシリーズ共通で、Neon(HTTP) と 汎用 Postgres(node-postgres) を切り替えます。Supabase では後者が使われ、プーラの接続枠を分け合うため 1 インスタンスあたり最大 3 接続に抑えています。
- テーブルは初回アクセス時に自動作成されます（冪等な `CREATE TABLE IF NOT EXISTS`）。マイグレーションの手動実行は不要です。

## 記録保管期間

日次記録3年 / 月次集計5年（各画面のCSV出力を月次で保管してください）。
